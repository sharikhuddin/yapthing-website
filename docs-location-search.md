# Clock, location and search

Clock replies use the device clock with IANA timezone/DST rules. They do not claim independent time synchronization. An explicit supported city or IANA timezone overrides device/selected timezone. Unknown places ask for a timezone; timezone alone never establishes a city.

Location is off by default. Users can enter a city/timezone, explicitly opt in to an IP lookup via ipapi.co (which receives the public IP), or request one browser location fix. Precise coordinates are immediately rounded to roughly a 1 km grid (coarser for inaccurate fixes); raw IP and precise coordinates are discarded. Automatic context expires after 15 minutes in memory. Forget, page exit and account changes clear it and invalidate pending callbacks. No watchPosition, location storage, account profiling, or automatic IP calls. Local questions may share the selected city/rounded area with search/AI, disclosed before opt-in. Existing chats may mention a city; forgetting location does not delete chat history. Provider infrastructure logs follow provider privacy policies. Browser device location is optional and may be unavailable in native containers; manual/IP alternatives remain available.

Explicit places override automatic context. Short location follow-ups use the preceding user question, never an assistant price claim, assumed currency or guessed jurisdiction. Auto research tries providers sequentially and stops on account/quota errors. Auto current-fact questions do not fall back to encyclopedias/paper indexes as if they were live weather/price sources. Snippets are labeled as snippets, invalid/private HTTPS links are rejected, and provider failure never becomes a fabricated current answer. Native automatic paid/cloud search remains disabled by existing policy. Its public encyclopedia indexes cannot verify live prices/weather.

Validation uses fixed-clock DST/midnight tests, privacy/permission/cancellation/TTL tests, provider fallback/auth/quota tests and chat integration tests. Android/iOS binary publication requires native build/device release gates; the website deploys independently through GitHub Pages.
